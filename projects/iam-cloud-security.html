AWS IAM Cloud Security & ABAC Access Control

I used Attribute-Based Access Control (ABAC) and the principle of least privilege with AWS IAM and resource tags. I gave a new intern user full control over development resources and protected production.

Access Model
ABAC & Least Privilege
AWS Services
AWS IAM, Amazon EC2
IAM Policy
NextWorkDevEnvironmentPolicy
IAM Group
nextwork-dev-group

1. What I Built

In this project I practiced securing AWS EC2 instances using IAM policies and resource tags:

  • Two EC2 instances with tags: Env=development and Env=production.
  • A custom IAM policy (NextWorkDevEnvironmentPolicy) with a condition on ec2:ResourceTag/Env.
  • An IAM user group nextwork-dev-group and a user added to it.
  • An AWS account alias for a custom sign-in URL.
  • Tested with the IAM Policy Simulator.

2. Policy Rules (NextWorkDevEnvironmentPolicy)

I learned how to combine Allow and Deny statements with tag conditions so the intern user can work freely in development without touching production or changing tags:

• Allow ec2:* where ec2:ResourceTag/Env = development.
• Allow ec2:Describe* on all resources.
• Deny ec2:DeleteTags and ec2:CreateTags.

3. Testing

I tested the permissions in two ways to verify that development access worked and production was protected:

  • In an incognito session: I stopped the development server (worked). I tried to stop the production server and got Access Denied.
  • IAM Policy Simulator: StopInstances on development = Allowed. DeleteTags = Denied.

4. Cleanup

I terminated both EC2 instances and deleted the test group and user.
