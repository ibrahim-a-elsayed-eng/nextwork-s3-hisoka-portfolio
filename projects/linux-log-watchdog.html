Linux Log Watchdog & Security Hardening

Continuous server-side observability daemon that monitors access logs, aggregates HTTP 404/500 errors, tracks suspicious client IPs, and runs inside a sandboxed systemd service jail.

Language & Tools
Bash (set -euo pipefail), awk, grep
Process Supervisor
Systemd (Jailed Oneshot Service)
Security Hardening
ProtectSystem=strict, NoNewPrivileges
Source Repository
GitHub / linux-basics-project

1. The Operational Problem: Silent Production Failures

In production Linux environments, applications write thousands of lines per hour to /var/log. Relying on manual inspections means:

  • Malicious actors probing endpoints with brute-force attacks go unnoticed until damage is done.
  • Spikes in 500 internal server errors remain invisible until customers complain.
  • Custom monitoring scripts running as root risk system compromise if exploited.

The Solution: A robust, hardened Bash watchdog daemon managed via isolated systemd unit configurations with strict kernel-level sandboxing.

3. Production Bash Script (log-monitor.sh)

Written with strict error handling (set -euo pipefail) to safely extract warning/error frequency windows:

07-harden-log-monitor/scripts/log-monitor.sh 
#!/usr/bin/env bash
set -euo pipefail

source_log="${SOURCE_LOG:-/var/log/demo-app/application.log}"
report_log="${REPORT_LOG:-/var/log/log-monitor/report.log}"
window_lines="${WINDOW_LINES:-200}"

if [[ ! -r "$source_log" ]]; then
  printf 'ERROR source log is not readable: %s\n' "$source_log" >&2
  exit 1
fi

recent_log="$(tail -n "$window_lines" "$source_log")"
warning_count="$(grep -c 'level=WARN' <<<"$recent_log" || true)"
error_count="$(grep -c 'level=ERROR' <<<"$recent_log" || true)"
timestamp="$(date --iso-8601=seconds)"
summary="$timestamp source=$source_log window_lines=$window_lines warnings=$warning_count errors=$error_count"

printf '%s\n' "$summary" | tee -a "$report_log"

if (( error_count > 0 )); then
  printf 'ALERT errors=%s source=%s\n' "$error_count" "$source_log" >&2
fi

4. Systemd Service Hardening & Sandboxing

To prevent privilege escalation, the watchdog runs under a dedicated service user with strict system protections:

07-harden-log-monitor/config/log-monitor.service 
[Unit]
Description=Scan the demo application log for warnings and errors
Documentation=man:systemd.service(5)
After=local-fs.target
ConditionPathExists=/var/log/demo-app/application.log

[Service]
Type=oneshot
User=log-monitor
Group=log-monitor
ExecStart=/usr/local/lib/log-monitor/log-monitor.sh
LogsDirectory=log-monitor
LogsDirectoryMode=0750
UMask=0027
NoNewPrivileges=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectSystem=strict
ProtectHome=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
